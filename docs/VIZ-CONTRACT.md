# Data wall widgets: contract for every widget

Reference: three screen recordings (a prompt-pipeline board, an AI-team board, a trading wall with a sphere of cells). Kleanthis redraws them as small canvas widgets fed by its OWN data. The look is the Data Vortex look: dark glass panel (#050b16), cyan #7DD3FC, amber #FBBF24, mono labels (ui-monospace), thin lines, soft glow.

## Files (a widget owns only these; never edit shell.js, home.js, stack-app.js or any other widget)
- `public/site/viz/<name>-data.js`: PURE model builder, UMD like `public/site/vortexdata.js` (CommonJS `module.exports` for tests, `window.SC.viz.<name>Data` in the browser). All numbers are computed here, never in the drawing code.
- `public/site/viz/<name>.js`: classic script IIFE exposing `SC.viz.<name> = { mount(host, model, opts) }`. `mount` appends one `<canvas>` (2D, no WebGL, no libraries) plus any plain text it needs into `host` and returns `{ destroy() }`. It resizes with the host (ResizeObserver), pauses when `document.hidden`, and draws ONE still frame when `matchMedia('(prefers-reduced-motion: reduce)').matches`. It reports a hovered or clicked record through `opts.onPick(item|null)`.
- `tests/viz/<name>_test.js`: standalone `node tests/viz/<name>_test.js`, prints `<name>: N passed, M failed`, exit code 1 on failure, no network, under 5 s. Test the data file with small made-up input AND with the real answers where the repo has them (see below).

## Rules (all of them, they are the platform's honesty rules)
1. No invented data. Every number on screen is a count, sum, share or age computed in `<name>-data.js` from the real answers. Nothing illustrative. Anything not available must show an honest empty state (a sentence in English and Greek), never a fake.
2. Only live, delayed or scheduled data may MOVE as data. Still data stays still; decorative motion (slow rotation, glow) is fine only if it does not look like a data change.
3. Never rank schools or cities, never compare indoor with outdoor, never present correlation as causation, no vehicle positions anywhere.
4. Every visible string is a pair `[english, greek]` in the model (a Greek translation a native reader accepts, plain words); the draw code picks with `SC.lang === 'el' ? 1 : 0`. No guillemets.
5. Node >= 22, CommonJS, no npm dependencies, no network calls inside a widget (the page fetches and hands the answers in), no `eval`, no inline script/style needs (CSP `script-src 'self'`). Keyboard/screen-reader: the host gets `role="img"` and an `aria-label` sentence built from the model, and the same facts exist as text via `model.textRows` (array of `[en, el]` strings) which the page will list under the picture.
6. Do not commit, do not push, do not run any other test file than your own. Do not start the server on a fixed shared port: if you need one, use `PORT=<random 4000-4999>` and kill it when done. Bash has no network; Playwright with swiftshader is installed: `NODE_PATH=/opt/npm-tools/node_modules` and `require('playwright')`; load your widget in a tiny static HTML page of your own under `/tmp`, screenshot it at 2 sizes (900x520 and 360x640), look at the PNGs yourself, fix what looks wrong.
7. Final answer to the lead: list of files, the model shape (field names), the test result line, one screenshot path, and any honest limit you found.
